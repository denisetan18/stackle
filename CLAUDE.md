# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Stackle (internally still "Daystack" in places) is a student study planner delivered as a **single file: `index.html`** (~3,100 lines of inline HTML, CSS and one `<script>`). There is no build step, package manager, linter or test suite. To run it, open `index.html` in a browser (needs internet only for Google Fonts and the AI APIs). Verify changes by reloading the page. `Stackle Screenshots (1).pdf` and `Timeline.docx` are reference material, not code.

## Architecture

All logic is global-scope functions and `let` state in one script. Rough layout, in file order:

1. **Constants/helpers** — time is modelled as **48 half-hour slots per day** (`SLOTS`, `slotLabel`, `timeToSlot`); dates are `YYYY-MM-DD` strings (`dateKey`/`parseDate`). Weeks start Monday (`mondayOf`, day index 0 = Mon).
2. **Auth/persistence** — two modes chosen by `FIREBASE_CONFIG` (top of the auth section; setup steps and Firestore rules are in the comment there). **Cloud mode** (config filled): Firebase Auth (username → `username@stackle.app`) + Firestore `users/{uid}` holding the whole data object as a JSON string (`dataJson`), plus public `profiles/{username}` for friends' stickers. Writes are debounced (`pushCloud`), and `listenRemote` applies other devices' edits live (last-write-wins, deferred while a modal/focus session is open). **Local mode** (config empty): accounts and data in `localStorage` key `daystack_users_v1` only. `ud` is the current user's data object; `hydrateState()` copies it into module-level variables (`variableTasks`, `fixedSchedules`, `assignments`, `completedSlots` Set, `stickers`, ...) and `collectUserData()`/`saveCurrentData()` copy them back. `saveIfChanged()` runs every 2s and diffs the JSON, so mutations don't each need to call save. **When adding persisted state, update `emptyUserData`, `hydrateState` and `collectUserData` together.** AI keys are intentionally not synced.
2b. **First-time tutorial** — new accounts start from `emptyUserData()` with `tutorialDone:false`; `renderTutorial` shows a floating coach card (welcome → fixed schedule → tasks → study caps in Settings → done) that opens the real modals. Existing accounts have no flag and skip it; Settings has a replay button.
3. **Scheduler** — `runScheduler()` rebuilds `assignments` from scratch every time: it sorts `variableTasks` by due date then priority and calls `scheduleRegular` or `scheduleExam`, which use `placeChunk`/`placePass` to find free slots after subtracting fixed schedules (`fixedOcc`, `expandFixed`) and already-placed blocks. Constraints: study window slots `STUDY_S`–`STUDY_E`, `MAX_CONSEC`, buffers (`NOW_BUF`, `SCH_BUF`), and per-day caps (`schoolDayCapHours`/`nonSchoolDayCapHours`). Exams split into study then revision phases (hardest chapter first); failures land in `lastUnscheduled` with a reason from `diagnoseWindow`. `scheduleFollowUp` adds review blocks after quizzes/confidence ratings. Any change to tasks, fixed schedules or caps must call `runScheduler()` to take effect.
4. **Rendering** — two parallel UIs share state: a desktop shell (`#desktopShell`, `renderDesktopSidebar`, `switchDesktopTab`) and a mobile shell (`#mobileShell`, bottom sheet, `switchTab`/`renderSheet`). `isDesktop()` chooses at init and on resize. `_renderGrid` draws the week grid for both; features touching the calendar usually need both shells checked. Modals (`openModal`, `open*Modal`) build HTML via template strings.
5. **Gamification** — completing blocks (`completeBlock`) awards stickers (`awardSticker`, rarities common/rare/ultra) and milestones; focus mode (`startFocusMode`) tracks tab-blur.
6. **AI layer** — user supplies their own key in Settings (`stackle_api_key`, `stackle_gemini_key`, provider in `stackle_ai_provider`), all in `localStorage`. Requests go **directly from the browser** to Anthropic (`callAnthropic`, with `anthropic-dangerous-allow-browser`) or Gemini (`callGemini`); messages are written in Anthropic shape and converted by `toGeminiContents`. `AI_MODELS` defines a `fast` tier and a `smart` tier used only when JSON parsing of the fast response fails (`aiCallJson`/`parseAiJson`). Gemini has an auto-fallback to `GEMINI_FALLBACK_MODEL` on 404. Used for file-to-tasks import, quizzes (`openQuizModal`) and confidence follow-ups. Model IDs are pinned strings; update them in `AI_MODELS` only.

`initApp()` (end of file) is the entry point after login: sets the week, runs the scheduler, renders the active shell, and starts the autosave and minute-refresh timers.
